# Quickstart: キウイ在庫管理 MVP

このガイドは、実装完了後に「動くこと」を確認するための手順。各ステップはspec.mdのUser Story（P1〜P5）に対応する。

## 前提

- Flutter（stable channel）と Chrome がインストール済み（`flutter doctor` で Web が有効）。
- Supabaseプロジェクトを1つ作成済み（[README.md](../../README.md) のセットアップ手順を参照）。

## セットアップ

```bash
# 1. 依存パッケージ取得
flutter pub get

# 2. Supabaseにスキーマを適用（SQL Editorで実行、または supabase CLI で）
#    - supabase/migrations/0001_init_mvp.sql
#    - supabase/migrations/0002_supplier_contract_date.sql（本feature追加分）
#    - supabase/seed.sql（開発用サンプルデータ、任意）

# 3. 起動
flutter run -d chrome \
  --dart-define=SUPABASE_URL=<Project URL> \
  --dart-define=SUPABASE_ANON_KEY=<anon public key>
```

## 検証シナリオ

### US1: 基本データを準備してログインする (P1)

1. 管理者アカウントでログイン → 管理者用画面（マスタ管理タブを含む）が表示される。
2. 品種を1件登録して保存 → 品種一覧に追加され、収穫記録画面の品種選択に表示される。
3. 現場スタッフアカウントでログイン → マスタ管理タブが表示されない現場向け画面になる。

### US2: 収穫・仕入れを記録する (P2)

1. 現場スタッフで収穫記録（圃場・品種・重量・個数・サイズ・コンテナ数）を保存 → 在庫一覧に「冷蔵保管」ステータスのロットが出現する。
2. 仕入れ記録（仕入先・仕入日・数量）を保存 → 同様に在庫として作成される。
3. 収穫記録を保存した直後、フォームがリセットされ次の入力にすぐ移れることを確認する。

### US3: 在庫・追熟状況を確認し、必要なら訂正する (P3)

1. 在庫一覧であるロットを「追熟中」→「追熟済み」に変更 → 一覧表示が更新される。
2. 誤って別の状態に変更したあと、任意の状態へ再訂正できる → `lot_status_history` に全変更が記録されていることをSupabaseのテーブルビューで確認する。
3. ステータスで絞り込み（例:「追熟済み」のみ） → 該当ロットのみ表示される。

### US4: 出荷を記録する (P4)

1. 在庫のあるロットを選び、出荷先種別・数量・配送方法を入力して保存 → 出荷記録が作成され、在庫一覧の残数が減る。
2. 出荷先が「体験プログラム」の場合、配送方法の入力が求められないことを確認する。
3. **回帰確認（FR-017）**: 残り在庫数量を超える数量を入力して保存しようとする → 保存がブロックされ、エラーが表示されることを確認する。

### US5: 在庫状況をひと目で把握する (P5)

1. 追熟完了目安日数に近いロットがある状態でホーム画面を開く → 「追熟完了が近いロット」に表示される。
2. ある品種の在庫が少ない状態でホーム画面を開く → 「在庫が少ない品種」に表示される。
